# systems/stu: STUD v3 reader

Offline reader for the beta 0.8 (build 24919) STU asset format: header, instance table, per-instance
layout-CRC check against the client's type registry, and decoding of every field kind into a generic
tree (`stu::Value`). Format and registry: [docs/STU.md](../../docs/STU.md) (§7 = this library).

```
cmake -S systems/stu -B systems/stu/build -G Ninja && cmake --build systems/stu/build
ctest --test-dir systems/stu/build                   # C++ tests + C API tests (plain C)
(cd systems/stu/go && go test -count=1 ./...)        # cgo wrapper (needs the build above)
systems/stu/build/stu_dump systems/stu/fixtures/graph_058000000000000F.stud   # JSON dump
```

| path | what |
|---|---|
| `include/stu/registry.h` | `stu::Registry::Client()`: the 3639 types, fields (offset, kind, element type, flags), names |
| `include/stu/reader.h` | `stu::Document::Parse` (raw file or as-loaded client image), `Decode(instance)` |
| `include/stu/value.h` | the decoded tree, `ToJson`, `DocumentJson` |
| `capi/stu.h`, `src/capi.cpp` | C API (`libow_stu_c.so`, `libow_stu_c_static.a`): documents, instances, values by field hash, JSON, registry |
| `go/` | Go module `owstu`, package `stu` (cgo over the C API): `Document`, `Value`, `LookupType` |
| `generated/registry_data.h` | generated by `tools/gen_registry.py` from `systems/data/client_stu_registry.json` + `names/` |
| `names/` | OWLib `TankLibHelper/DataPreHashChange` KnownTypes/KnownFields/KnownEnums (the 0.8-era hashes) |
| `fixtures/` | test blobs dumped from the client (see its README) |
| `tools/` | `gen_registry.py`, `dump_live.py` (dump a resident STU via Prometheus MCP), `unfix_image.py` (loaded image → raw file), `stu_dump` |
