### GameClockSystem (`0x15c4be8`; game #1, session #0)
Advances the EA's timing/clock object (EA+0x218) once per render frame: stores dt, accumulates total time, bumps a frame counter, then updates the clock's command-frame/time-scale state.
- tick: clk=*(EA+0x218); clk+0x20=dt; clk+0x28(double)+=dt; clk+0x30=scaled int64 time; clk+0x38++ ; then FUN_7ff650ce63a0(clk,dt): converts dt to microsecond-ish ticks with a debug speed-up/slow-down modifier from flag byte clk+0xa8 (+/-200 or +/-1000), smooths two rate values at clk+0x80/+0x84 toward targets (clk+0x98*16000), and calls FUN_7ff65100e950(clk,ticks) to advance the CF clock.
- interacts with: EA clock object EA+0x218 (same object later read by CommandFrameSystem via +0x50 list of pending CFs), anti-tamper page CRC checks (DAT_7ff6517fd478) - noise
- fixed-step (command frames): False
- server: Needed conceptually (the server needs its own 16 ms clock), but this is the client's clock driver; server should implement its own tick clock rather than port this.
- slots: on_initialize `0x7ff650580c30`, on_tick `0x7ff650c7d4b0`
- functions: `0x7ff650c7d4b0` OnTick; `0x7ff650be3be0` EA->clock getter (returns EA+0x218); `0x7ff650ce63a0` clock advance w/ time-scale flags, feeds CF accumulator; `0x7ff65100e950` clock tick-accumulate (produces CF list)
- evidence: First system in game EA; only touches EA+0x218: writes dt at +0x20, accumulates double at +0x28, increments frame counter +0x38; 16000 constant (16 ms CF in us) in FUN_7ff650ce63a0.

### ClientCosmeticsTickSystem (Chroma keyboard lighting + option-driven toggles) (`0x15c23a8`; game #2)
Game-EA per-frame client helper. Pushes the local player's hero colour to the Razer Chroma keyboard-LED manager (6x22 key grid). Also counts down a timer in lobby comp 0x50, and enables or disables per-entity feature objects according to the user's option bytes.
- tick: 1) Anti-tamper rdtsc check (ignore). 2) lobbyEA comp 0x50 (singleton, 0x720 bytes, profile/options) +0x144 -= dt, clamped at 0. 3) FUN_7ff650bfcd40: gets the LED manager via (*DAT_7ff6517fe448)->vfunc+0x2b8, gets the colour vec4 at +0x168 of the local player's comp 0x3F -> hero data (FUN_7ff650bfcc00, falls back to a default colour), packs it to RGBA8 at mgr+0x454, sets the dirty flag and ticks the manager (FUN_7ff650893560, which calls the SDK fnptr with (2, int[6][22]). 4) FUN_7ff650bfce30: if the EA is a game EA, walks the handle list in singleton comp 0x5E (count +0x20). It resolves each handle via FUN_7ff650cc3f60 (entity-id + index -> object in the entity's 0x1e0 list) and reads option id +0x130 against the lobby comp 0x50 option bytes (+0x2ce / +0x454 [profile*0xc3 + id]). It then calls FUN_7ff650ce5bc0 (enable, +0x134=1) or FUN_7ff650ce5c90 (disable, +0x134=0).
- callbacks: OnInitialize (not defined in Ghidra, 0x7ff650bfcae0) registers {callback 0x7ff650bfcaa0, this} into global object [0x7ff6517fe458]+0x730/+0x738. PreDelete (0x7ff650bfcb00) clears them.

### NetworkEventSystem (`0x15c3b90`; game #3)
Client side of the UDP game-server connection. Owns the transport object (+0x10, 0x350 bytes). Each frame it pumps the transport, then sends the queued connection events (connect, disconnect, packet received and so on) to its virtual handlers. Received game packets are demultiplexed by channel to registered channel handlers (list at +0x20), which read entity ids and bitstreams.
- tick: Reads the 'disableTimeout' cvar; takes the transport lock (+0x150) and calls UdpTransport_Tick; splices the transport event queue (+0x238) and sends each event by type: 1 goes to vfunc 0x88 (__HandleConnectEvent), 2 to 0x98, 3 to 0x90, 4 to 0xa0 (packet received), 5 to 0xa8. It then frees the event buffers and calls vfunc 0x80, which copies net stats (ping/RTT, a 0xe0-byte stats block) into globals and the netgraph object from FUN_7ff650c2c410 when the game EA state is 4.
- callbacks: OnInitialize allocates and constructs the transport (FUN_7ff650e31640) and stores the local port/id at +0x38. PreDelete tears it down.
- interacts with: UDP transport (UdpTransport_Tick), game EA +0x170 state (==4 in-game), netgraph/stats object FUN_7ff650c2c410, EA entity-id hash (EA+0x10) to resolve entity ids in packets, registered per-channel packet handlers (+0x20 list, vfuncs +0x30/+0x38), global event bus DAT_7ff651797fa8+0x3028 (connect event)
- fixed-step (command frames): False
- server: Client-only (client end of the transport). The server needs the matching peer protocol: a connect handshake, then type-1 packets with an entity-id bitstream for each channel.
- slots: on_initialize `0x7ff65102f480`, on_tick `0x7ff65102f580`, pre_delete `0x7ff65102f530`
- functions: `0x7ff65102f580` OnTick: transport tick + event dispatch; `0x7ff65102f480` OnInitialize: create transport; `0x7ff650c4fd40` vfunc 0x88 __HandleConnectEvent: reset stats, broadcast connect, notify channel handlers; `0x7ff650c500a0` vfunc 0xa0 packet received: frame-time stats; type 1 = per-entity bitstream sent to channel handlers, type 0xf = raw sent to the last handler; `0x7ff650c4f7f0` vfunc 0x80 post-tick: copy net stats into globals/netgraph
- evidence: Strings 'NetworkEventSystem_C::__HandleConnectEvent', '::__Disconnected', '::DisconnectFromInstance'. Calls UdpTransport_Tick. Handles event types 1-5. 'disableTimeout' cvar.

### JamSystem (network connection / JAM link pump) (`0x15c3920`; game #4)
Owns the client's JAM network connection object (sys+0x28, name string 'JamSystem (%s)'). Each frame it updates a 1000-sample bandwidth/message-rate window, pumps the incoming-message queue, connects to a pending host:port, times out stale connections ('CheckConnections: Timing out...') and sends a periodic 250 ms keepalive/heartbeat message while connected.
- tick: FUN_7ff650c462a0: rolling 1000-sample stats window (dt in ms). If not connected and a target address string exists (sys+0x3000) it resolves/connects (FUN_7ff650c45030, only when the global connection state at EA+0x170 +0xdc != 4). FUN_7ff650f02340(conn) = service the connection. FUN_7ff650c44e60 drains a critical-section-protected event queue (connect/disconnect events type 0/1). FUN_7ff650c45dc0: if link state (EA+0x170 +0x94)==3 and more than 5000 ms since last receive, logs '__CheckConnections: Timing out' and disconnects. FUN_7ff650c45b70: state 2 -> reconnect after 10 s; state 4 -> every 0.25 s builds a message and sends it through the EA's JAM handler at EA+0x1d0 (vtable+8).
- callbacks: OnInitialize: sets conn+0x268=5 (flags), names the connection 'JamSystem (%s)', registers sys+0x30 as a listener on conn+0x20, calls conn vtable+0x10 (start). PreDelete tears the connection down.
- interacts with: network connection object (sys+0x28), EA+0x170 connection/session state, EA+0x1d0 JAM message sender, global game EA DAT_7ff651797f90
- fixed-step (command frames): False
- server: Client transport only. A server needs the matching peer: accept the link, answer heartbeats and avoid the 5 s receive timeout.
- slots: on_initialize `0x7ff650c44d40`, on_tick `0x7ff650c44f80`, pre_delete `0x7ff650c44e00`
- functions: `0x7ff650c44f80` OnTick; `0x7ff650c44d40` OnInitialize (name 'JamSystem (%s)', register listener); `0x7ff650c462a0` 1000-sample bytes/messages rate window; `0x7ff650c45030` connect to pending address (resolve host:port); `0x7ff650c44e60` drain connection-event queue; `0x7ff650c45dc0` CheckConnections 5 s timeout; `0x7ff650c45b70` reconnect / 250 ms heartbeat send via EA+0x1d0
- evidence: Strings 'JamSystem (%s)' and '__CheckConnections: Timing out a...'; 5000/10000 ms timeouts; 0x3e800000 (0.25 s) resend timer; send through EA+0x1d0 vtable+8.

### ClientLobbyMessageSystem (`0x15c3a58`; game #5)
Pumps the lobby-server connection. It drains a thread-safe queue of link events and handles link-up/link-down for connection type 0xd (LobbyServer), then dispatches the queued incoming lobby RPC/messages.
- tick: FUN_7ff650c47360(sys+0x10): pops events from a critical-section-guarded deque at +0x98. Event 1 with type 0xd is link down (FUN_7ff650c46c10: 'HandleLinkDown: Pending connection...' / 'Lost connection to LobbyServer', notify listeners). Then FUN_7ff650f034e0 drains and dispatches the incoming message list.
- callbacks: PreDelete (0x140c668a0) forwards to 0x140c66fb0 on sys+0x10, which shuts down the connection handler.

- fixed-step (command frames): False

- slots: on_initialize `0x7ff650580c30`, on_tick `0x7ff650c46820`, pre_delete `0x7ff650c468a0`

### MapLoadSystem (MapSystem) (`0x15c3118`; game #6, session #1)
Map load/unload state machine. Holds current map id; walks a phase byte (sys+0x10: 2..8), requesting map resources and notifying all map-load listeners registered at EA+0x180 at each phase.
- tick: switch(sys+0x10): 2 -> FUN_7ff650c194a0: resolve map asset (type 0x9e, id sys+0x18), request its load + preload several 0x6e (type 0x06E) resources, call listener slot1 (+8) 'begin', phase=3; 3/4/5/6 -> call listener slots +0x10/+0x18/+0x20/+0x28 on every listener and advance; 7 -> FUN_7ff650c195e0: listener slot +0x30 'load complete', release previous map resource (sys+0x20), phase=8 (loaded). States 3/4/5/7 are wrapped by gated helpers (c1a080 waits on resource ready via sys+0x53 flag, and calls world/scene object EA+0x130 vfunc+0x40(mapId)).
- callbacks: OnInitialize (0x7ff650c17f90, not defined in Ghidra: 'mov byte [rcx+0x10],2; mov al,1; ret') sets phase=2 so loading starts immediately.
- interacts with: map-load listener list EA+0x180/0x188 (systems like MapRootEntitySystem implement slots 1..7), resource manager (FUN_7ff6509a2d30 load request, FUN_7ff6509a5120/abac0 release), world/scene object EA+0x130, DAT_7ff651813e18+0x1e8 (client app)
- fixed-step (command frames): False
- server: Server must load the same map data (spawn map entities, collision), but the client listener fan-out/streaming is client-side; a server needs an equivalent map-load step, not this code.
- slots: on_initialize `0x7ff650c17f90`, on_tick `0x7ff650c17fd0`
- functions: `0x7ff650c17fd0` OnTick dispatcher (phase switch); `0x7ff650c19340` phase step / listener fan-out; `0x7ff650c194a0` phase 2: request map + prefetch, notify begin; `0x7ff650c195e0` phase 7: notify finished, release old map; `0x7ff650c1a080` phase-3 gate: wait for map resource, bind to world; `0x7ff650c1b160` (seen from replay reset) map unload

### PvpSystem (PvP game-state notifier / match-end watcher) (`0x15c1c48`; game #7, session #2)

When a certain system's state byte equals 7 (likely match finished), it runs an end-of-game path that sets a flag on that system.
- tick: comp 0x24 = FUN_7ff650c386f0(EA) (iteration list +0x360). If +0xc0 > 0: notifier = EA->vfunc+0x80(); notifier->vfunc+0x10(0x2000000); comp+0xc0--. - writes: 0x24 (+0xc0 countdown) 0x24 (+0xc0 countdown)
- interacts with: EA world-change notifier (EA vfunc+0x80, same one used by StatescriptSystem 0x15c2e20), system typed 0x7ff6517986a8 (game-state holder, state 7)
- fixed-step (command frames): False

- slots: on_initialize `0x7ff650580c30`, on_tick `0x7ff650bfb850`

### MirrorSystem (replication receive) (`0x15c28c8`; game #8, session #3)
Applies received replication (Mirror) messages to the ECS: create, update or destroy networked entities. It also triggers one-time local-player setup once the local player entity exists, and runs integrity (anti-tamper) CRC checks on code pages.
- tick: Gets the local player entity id (FUN_7ff650bfd2f0). Calls FUN_7ff650bff690, which does a random CRC32 check of one 4 KB code page against a table (DAT_7ff6517fd478) and reports a mismatch. It then drains the queued replication batches (+0x98/+0xa0) through FUN_7ff650bffdf0: op 1 = create entity (FUN_7ff650c00d20), op 2 = update existing entity (FUN_7ff650c00560), op 3 = destroy (FUN_7ff650c00c80). When the local player entity first resolves (flag +200), it runs a one-time init (FUN_7ff650c19340). There is also a 500 ms tick-count anti-debug check.
- writes: many (component state deserialized from mirror data) many (component state deserialized from mirror data)
- interacts with: NetworkEventSystem (source of batches), EA entity-id hash, entity create/destroy, anti-tamper page CRC table DAT_7ff6517fd478
