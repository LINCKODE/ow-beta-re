# Statescript config-var catalogue (client build 24919)

Per-type table of the **278 config-var types used by the graphs of the build** (243 of them by the 296 graphs
resident on Temple of Anubis), grouped by family. Generated by
`systems/data/statescript/tools/configvar_catalogue.py` from `systems/data/statescript/configvar_catalogue.json`
(machine-readable, all 328 types, with evaluator vtable / `GetValue` RVA / field layout / use counts). Semantics
and the interface: [StatescriptConfigVars.md](StatescriptConfigVars.md). T038.

Columns: **inputs** = the type's fields and what they are used for (`CV` = another config var, evaluated in the
same instance); **→** = output `StatescriptPrimitive` type (`varies` = passes a value through); **computes** =
what `GetValue` (+0xD0) does, incl. failure behaviour (false = the caller's getter uses its default); **reads** =
what it depends on (`literal` / `pure` = only its operand config vars / `instance vars` / `entity state` /
`local player` / `match/game state` / `client/platform` / `UI` / `assets` / `random` / `server` = no client
evaluator); **class** = the client has an evaluator for the type (no = base evaluator, GetValue returns false);
**uses** = resident / all graphs; **tag** G = read in Ghidra, ? = designed from name / fields / consumers.
Names in *italics* were recovered by CRC match (StatescriptNodeCatalogue.md). Component numbers are ECS
component ids (docs/ECS_Components.md). RVAs throughout (Ghidra = `0x7ff64ffe0000 + RVA`). In the texts `X` / `inst` = the StatescriptInstance passed to `GetValue` (instance vfunc `+0x30` returns the instance itself), `SyncMgr` = `inst+0x10`, `EA+0xB0+N*0x18` = the list of components of type N in an entity admin.
