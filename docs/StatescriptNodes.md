# Statescript node types: priorities, specs, coverage (T054)

What the runtime library (`systems/statescript`) implements per node type, in which order the rest is done, and
the specification of each type as read from the client. Background: the data model and execution semantics are
[StatescriptRuntime.md](StatescriptRuntime.md) §1–3, the library §5, the sync protocol and every type's state data
[StatescriptSync.md](StatescriptSync.md) §4, the type catalogue [StatescriptNodeCatalogue.md](StatescriptNodeCatalogue.md).

**Tags**: [G] read in Ghidra (RVAs; Ghidra = `0x7ff64ffe0000 + RVA`; decompiler names `FUN_7ff6…` are Ghidra
addresses), [L] live, [T] checked by a library test on real graphs, [?] inferred / designed.
**Rule**: per type, spec first (the client class in Ghidra, or a design marked [?] for server-only
types), then the implementation, then a test.

---

## 1. Capabilities: what the library tells a host

The library keeps one registry of what it implements (`include/statescript/capabilities.h`,
`src/capabilities.cpp`), so a host (the instance server, T053) decides from it which states it simulates and
corrects, without per-type lists of its own.

- **Client types** (`ClientTypes()`): all 719 node / state / config-var types of the client, generated by
  `tools/gen_type_table.py` from the node catalogue (T014) and T052's `state_data_formats.json` into
  `generated/type_table.h`: kind, the STU type whose client class implements it (exact or nearest registered
  ancestor, §1.8 of the runtime doc; 0 = none: server-only logic), the class's priority layer, and for states
  whether the type is has-update and whether its local / remote state-data formats are non-empty and identical.
- **Level** per type (`Capability(type)`): 0 unmodelled (plugs and lifetime only, counted in
  `SyncManager::unmodelled_*`), 1 presentation (client presentation: a no-op is the right server behaviour),
  2 designed (no client class to follow, or partial) [?], 3 exact (the client class read in Ghidra), 4 verified
  (exact and checked against client recordings: fixture replays, T052/T053 shadow compare).
- **Data** per format (local = the owner's rollback packets, remote = other clients' updates): none (the format
  is empty), writer (the runtime writes it from its state per the spec), echo (not produced: only the bits an
  import supplied can be written back). A type whose local and remote formats are identical uses the local
  writer for both.
- **Changes** (`ss_sm_state_changes`): a state's count moves on begin / re-enter / end and whenever its
  **change key** differs after a top-level `RunCommandFrames` (default: its whole local data; types whose data
  moves with time write only their event fields: Ability flags / cooldown running / cooldown epoch / stack
  predecessor, WeaponVolley counter + serial, ChaseVar's four flags, Anim serial + has-animation). A host sends a
  state again exactly when this moved.
- **Executed actions** (`ss_sm_actions`): the client's "action executed" records (sync spec §2.9): recorded
  after an action's DoAction on instances with a positive id, before its out plug (`G:0xf47740`); actions whose
  class replaces Execute record nothing (StopScript `G:0xf68cb0`). The last 256 CFs are kept.
- **C API** (`capi/statescript.h`, T053 owns the Go side): `ss_runtime_type_caps` / `ss_runtime_type_cap`,
  `ss_runtime_graph_node_types`, `ss_sm_state_data2(local, full)` (returns `SS_ERR_UNIMPLEMENTED` for echo without
  imported bits or a missing remote writer), `ss_sm_state_data_refs` (instance ids the data names: the client
  crashes on an unknown one), `ss_sm_actions`, `ss_runtime_graph_remote_nodes`, `ss_runtime_graph_bit_counts`
  (the graph's `m_nodesBitCount` / `m_statesBitCount` / `m_remoteSyncNodesBitCount` / `m_syncVarsBitCount`: STU
  fields of the asset, not computed).

**Adding a type**: implement it (`nodes.cpp` / `states*.cpp`), add its row to `kImplemented` in
`src/capabilities.cpp` (level, local / remote writer), add a test, write its spec entry in §3 and update §4.
Nothing on the server side changes.

### 2.1 Triage and batches

Per type the client class's overridden hooks (`tools/class_hooks.py`: vtable slots against the base class, from
the binary) tell whether it has behaviour to read. Order of work (Genji's remaining abilities first,
then the types shared by most heroes, then brains / objectives):

   actions / condition (ArrayAdd, ArrayRemove, ArrayContains, CycleIndex), Watch, ActionSwitch, the unnamed

   AndGate, CreateEntity, the unnamed state `cd396790` (29 hero uses: begin / timer / finish), VoiceStimulus
   (brains), the LogicalButton state's own hooks.

   CosmeticEntity, ClientonlyController, PopulateTips, UXScreen, UIInWorld, UXReticleOverride, UXToast,
   BroadcastChat, the Camera states, GamePadVibration, BeamEffect, SprayEffect, TargetEffect.

   types (LimitAim, Invisible, CameraTransform, PhaseOut, AimSpeed, TimeScaleAnimation, CameraChase, WeaponAim,
   ImpactEffectOverride, `2785fbdd`: §3.2), TrackMovement, MovementMod, MoveTo, LedgeClimb, WallMove,

   Unkillable, CombatModFilter, Pet / SpawnPet, TeleportTo, BroadcastGameMessage, ApplyTargetTags, …

## 3. Type specifications

### 3.1 SubScript (`3db862c4`; base `STUStatescriptStateSubScriptBase` `06bcf0df`) — verified [G][T][L]

p1 class, vtable `0x1621978`, 0xC0 bytes. Node fields: `+0x100` init data `7eb65d0d` (inline
`STUStatescriptSubScriptInitData` `550c2aa4`: `ec9f34a6` = `m_out_Var` (a Dynamic path in the child),
`5180e750` = `m_value` (a config var evaluated in the parent)), `+0x110` `m_onAbortPlug` (`41ba609a`), `+0x118`
`m_onFinishedPlug` (`fe841c79`), `+0x120` keep-alive `db3a2efb` (u8), `+0x121` `916d18ce` (u8, "don't end with
the child"), `+0x128` `m_statescriptGraph`. State fields: `+0xA8` i16 child instance id, `+0xAA` u8 keep-alive.

- **Begin** (`+0x108`, `0xf70a10`; after activation, before the OnBegin plug): child id := 0. The graph =
  `+0x258` (`0xf71020`: `m_statescriptGraph` evaluated in the instance bag). If there is one and the instance's
  depth is not 255: `+0x260` (`0x10ccc00`) creates the child unless the instance is in server-apply mode: a
  cached detached child of the same graph (instance `+0x50`, `0xf4c710`: its bag reset) is re-added (component
  `+0x78`), else component `+0x70` (`0xcca630`) → `CreateInstance` (`0xd13810`) with **kind 1** (a kind-1/2
  instance is **not instantiated at creation** even while the sync manager executes), the parent's mirrored flag
  (0x8) and owner. Keep-alive := node `+0x120`. If a child exists: child `+0x1A` parent id (flag 0x4000 when ≠ 0),
  `+0x1C` = this state's index, `+0x20` = this state's serial, depth + 1, `+0x90` creator id. Then **for each
  init entry in order**: the value = `m_value` evaluated in the parent (`0xf5dac0` on the parent's instance
  bag), the target = the child bag's resolution of `m_out_Var` (vfunc `+0x128` → {instance id, var id}); a
  **SetVar notification** (type 4, flags `|= 8`, time = now) goes to that instance's queue (sorted), or through
  the sync-manager queue for id 0 (the entity bag); sync manager `+0x359` := 1. Then, with this state's flag 0x10
  (exit taken) held, `0xf4caa0` instantiates the child (its plain entries are queued **behind the SetVars**) and
  the child is **processed at once** (vfunc `+0x138(0)` = ProcessInstance): its entries, the input writes and
  everything they start run inside the parent's begin, before the parent's OnBegin / Subgraph plugs. If no
  child was created: unless `916d18ce`, a Lifetime **finish** at now.
- **Child ids** (component `+0xA8` / `+0xAA`): mirrored → `0x103b6a0`: max(existing ids, 0) + 1; if that is
  above 0x7F, `0xcca250` takes the smallest id in [1, 0x7F) not in use. Local → `0x103b750`: min(existing ids, 0)
  − 1. (T041's "smallest unused" was the fallback only.) [?]: whether stopped-but-not-freed instances count; the
  library ignores stopped instances.
- **The child stops** (instance Stop `0xf500e0`: stopped flag first, then every active state aborted, so their
  plugs follow no links): if its parent's state at `+0x1C` is active, a SubScript with the same serial (`+0x20`)
  and child id: that state's child id := 0 and, unless `916d18ce`, vfunc `+0x1D8(0)`: a Lifetime **abort** at
  now.
- **End** (deactivate `+0x168`, `0xf70e10`, reason ≠ 5): unless keep-alive or the instance is in server-apply
  mode: the child is unlinked (flag 0x4000 cleared, parent fields 0) and asked to stop at now (`0xf4fff0`: a
  StopInstance notification); child id := 0. Plugs: finished → `+0x118` (`0xdc96d0`), aborted → `+0x110`.
- **State data** (writer `0xf70ea0`, reader `0xf70f40`): **local only**: small(child id: 0 + 4 | 1 0 + 8 |
  1 1 + 16 bits) + bit keep-alive; the remote format is empty. The id names an instance: `ss_sm_state_data_refs`
  returns it.

Library: `SubScriptState` (`src/states.cpp`), `SyncManager::CreateChild` / `AllocateId`, `Instance::Stop`
(parent coupling). Tests (`tests/test_nodes.cpp`, graphs `0x3ca` → `0x3b6` from CASC): the child's id (parent 5 →
6; local −1 → −2), parent / slot, the three input values set before the child's entry, the child processed
before the parent's plugs, the data bits `0 0110 0`, the child's stop aborting the state, the state's abort
stopping the child. **Client recording** (`fixtures/raw_subscript_3ca.jsonl`: Prometheus `play_script 0x3ca` on the
game EA, 2026-09-27): the library reproduces every instantiate / notification / begin / link of the begin CF in
order (test `subscript_replays_client_trace`), given the two host answers the child reads (a target-tag search that
finds an entity, `GetEntityExists`).

### 3.2 SendGameMessage (`8b6a3312`, base `f9f1e339`) — exact for the own entity, other targets designed [G][T]

p2 class vtable `0x15db930`, DoAction `0xd794f0`. Fields: base `+0x88` `m_params` (`a51f99c5*[]`: `+0x08`
`c76b6366` key identifier, `+0x18` `m_value` config var, iterable), `+0x98` `m_gameMessage`, `+0xA0` `694d2b8b`
(instigator); `+0xA8` `m_targets` (iterable).

- **Nothing on a mirrored instance** (flag 0x8): on the client a server-created (hero) instance never sends,
  predicted or not; its messages are the server's to deliver.
- Message = the GUID of `m_gameMessage` (none: nothing). The own entity = the component's entity.
- `m_targets` is iterated (SS_CVIterator, §3.3); ENTITY entries that are valid are collected: the own entity
  sets a flag, the others go to a list.
- Sender = the own entity; instigator = `694d2b8b`'s value if it is an ENTITY, else the instance's owner var
  `$1b`, and the own entity if that is invalid. Params: for each `m_params` entry with a key, every value
  `m_value` iterates to is added under the key.
- **Delivery: the own entity only**: if it was a target, the message goes to every instance of the own sync
  manager (`0xf50770`, synchronously inside the action: parameter SetVars + TraverseFrom at now, §3.10 of the
  runtime doc). The list of other targets is built but not used on the client: delivering to other entities is
  the server's (library: through `SyncManager::entity_resolver`, [?]).
- Library limits [?]: one entity per `m_targets` (single-value config vars), one value per parameter.

- **The networked variant `4027e912`** (same base, DoAction `0xd7abb0`) [G]: the client runs it only for an
  (instance, node) that the server's actions section registered (net-sync `+0x130`, `0xd09f20`: found and
  removed); it then delivers to **every** target, the own entity included, through the target's sync manager
  (`0xf457c0`: every instance; when the message came from another entity and an entry fired, a nested flush
  `RunCommandFrames(cf, 0)`). A server runs it outright (library: Role::Server delivers, Role::Client does
  nothing). The same delivery is used for SendGameMessage's other targets [?].
- `5bea9b4b` (m_params, m_condition, m_gameMessage; DoAction `0xd7a460`) is gated the same way and posts the
  message to a global entity admin's sync manager (`DAT 0x1833e18`: UI / lobby) when `m_condition` holds: not
  modelled (presentation on the client).

Test: graph `0x037` (a reply: a GameMessage entry writes the sender to `$28`, SendGameMessage `0x…12f` to `$28`):
to self (the own sync manager's instances get it), to another entity (through the resolver).

### 3.3 Arrays: Dictionary vars, iteration, ArrayAdd / ArrayRemove / ArrayContains / CycleIndex, expression ops 32–34 and 36 — exact [G][T]

**Dictionary vars** (var class `0x1607d20`, entries `{Primitive key, Primitive value}` 0x20 B at `+0xA0`, count
`+0xA8`). A write goes through the bag (`+0x170` = `0xf633b0`: path → bag, `0xf62cb0` get-or-create the
Dictionary var, a var of another class replaced with its subscribers kept) to the var's begin (`+0x170` =
`0xf61530`: write-priority check `0xf3eb00`, else rejected; the user stored; dirty) and end (`+0x178` =
`0xf61660`: computes the changed range for the sync's range update, then **always** notifies list-0 then list-1
subscribers). Writers use the null user (priority 1). More than 200 entries is a logged graph violation
(`0xf51590`), nothing else.

**Iteration** (SS_CVIterator `0xf5a740` / `0xf5a7f0`): an `STUConfigVarArray` (`13ba10f6`) yields its
`m_configVars` in order, nested arrays flattened (4 levels); an `STUConfigVarIterable` (`8cb6be1c`) subclass uses
its evaluator's iterator slots `+0xE0` / `+0xE8` (host game state: not modelled, yields nothing, counted); any
other config var goes through `0xf4d330`: a Dynamic path to a Dictionary var (bag `+0x158`) yields its entries,
anything else **one entry {BYTE 0, its value}** (value BYTE 0 when it has none).

- **ArrayAdd** (`0cdc2e1a`: `+0x88` `m_index`, `+0x90` `m_out_Array` (Dynamic), `+0x98` `m_key`, `+0xA0`
  `m_value`, `+0xA8` `a7e46ea2` unique; execute `0xf67fb0`, add `0xf68200`): index = `m_index` as int (default −1;
  > 200: violation, nothing). **With `m_key`**: bag `+0x130` → `0xf60cd0`: key = `m_key`'s value, value =
  `m_value`'s (INT 0 defaults); an entry with an equal **non-numeric** key (`0xf61180`: numeric keys never match)
  is overwritten in place if it is at `index`, else removed; then {key, value} is appended (index < 0 or ≥ size)
  or inserted at `index`. **Without**: every element of `m_value` (iterated; stopping when the iterator reaches
  the target's own entries): a numeric-keyed element (BYTE / INT / FLT key: scalars) is skipped when unique and
  some entry's value equals it, else appended (index out of range) or inserted at `index++`; a non-numeric-keyed
  element overwrites the value of the first entry with an equal non-numeric key, else is appended / inserted.
  Then commit. Equality is the loose `==` (`0xee99c0`).
- **ArrayRemove** (`a88eb9de`: same fields; execute `0xf684e0`, remove `0xf68730`): needs `m_out_Array` and
  one of key / value / index. **With `m_key`**: bag `+0x138` (`0xf62f10` → `0xf60ee0`), an **existing** Dictionary
  only: remove every entry whose key equals (and, with `m_value`, whose value equals). **Without**: begin a write
  (creating the var); index ≥ 0: remove that entry if in range; index < 0 with `m_value`: remove every entry
  whose value equals the value of any element of `m_value`. Commit either way.
- **ArrayContains** (condition `5720b660`: `+0x90` `edfb51d3` the array, `+0x98` `m_key`, `+0xA0` `m_value`;
  evaluate `0xf701f0`): false without the array or without both key and value, or when one that is set yields
  nothing; else true when some iterated element matches: value only → its value, key only → its key, both →
  both.
- **CycleIndex** (`17c9f80b`: `+0x88` `m_count`, `+0x90` `m_condition`, `+0x98` `188934cd` backwards, `+0xA0`
  `m_out_Index` (Dynamic), `+0xA8` `aca9b916` fallback; execute `0xf689e0`): count outside 1…200 → the out
  index := `aca9b916` (int, default −1). Else start = the current out index clamped to [0, count − 1]; step ±1
  with wrap-around; for each candidate a **value provider** (§ op 36) answers the identifier `0x0A4…0C` with the
  candidate (INT) while `m_condition` is evaluated; the first candidate for which it is truthy is written;
  after a full cycle without one, the fallback is written.
- **Expression ops 32–34** (both interpreters; instance `+0xF0` then the `+0xD8` lookup): the Dictionary var of
  `m_dynamicVars[a]` (in another entity's entity bag after op 35 in the typed interpreter); key BYTE / INT / FLT =
  position (FLT rounded half away from zero), else the first entry with an equal key; 32 → value, 33 → key, 34 →
  INT index (−1); not found → INT 0. The **float** interpreter (`0xf6adc0`) rounds the stack value to the key and
  converts the result: BYTE → 1 / 0, INT and FLT as floats, **anything else 0** (a list of GUIDs reads 0).
- **Op 36** (instance `+0xC8` = `0xf4d580`): the sync manager's value providers (`+0x410`, count `+0x418`),
  walked last to first, are asked for the last id of the Dynamic operand's path (`0xf5a6f0`); the first that
  answers wins. None: FLT 0 [?].

Library: `VarBag::BeginDictionaryWrite` / `CommitDictionary`, `Iterate` (`config_vars.cpp`), `nodes.cpp`
(ArrayAdd, ArrayRemove, ArrayContains, CycleIndex), `SyncManager::value_providers`. Tests: graph `0x158` (a

### 6.3 The capture point (`0x028`)

**CapturePointEvents** (`0119c536`, client class vtable `0x161b520`) [G]: activation (`0x10bcbb0` → `0xf47f10`) owns its
progress var `84e42246` (`+0x168`, `$009a`) with the state-defined bit (user {instance, state, 0x81}); the value
(`+0x228` = `0x10bcc50`) is the float at component 0x1a `+0xb4`, i.e. the mirrored capture area's `794d7691` (the

(`capture_radius`) [?: the shape assets are not read]. A server can take it as the reference for its host.
